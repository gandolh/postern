# Task 18: Deploy at /webmail

## Context

Postern ships through the estate's deploy tool, `../vps-deploy`, like every
other app. Three changes go there:

- a static-site stack for `/webmail`;
- the `/webmail-api` route, declared in the **mail** stack, because it proxies
  to Stalwart's loopback port, which the mail stack owns (a second stack
  claiming the port fails synth);
- per-route security headers, which that repo's Caddy renderer does not
  support yet.

Deploying is an owner step. Read `../vps-deploy/corpus/` (its CLAUDE.md and
decisions) before editing there, and follow that repo's conventions and
commit style.

## Files you OWN

- In `../vps-deploy`:
  - `../vps-deploy/stacks/postern.ts` (new): a static site, source
    `../postern`, build `npm run build`, output `web/dist`, prefix
    `/webmail`, SPA fallback, headers from step 3;
  - `../vps-deploy/stacks/mail.ts`: the `/webmail-api` route (proxy to its
    HTTP port, prefix stripped), with a note on why it lives there;
  - `../vps-deploy/lib/constructs/caddy.ts` and
    `../vps-deploy/lib/core/synth.ts`: optional per-route response headers;
  - `../vps-deploy/app.ts`;
  - `../vps-deploy/infrastructure/Caddyfile`: regenerated by synth, never by
    hand.
- In this repo: `README.md` (how it is deployed),
  `corpus/wiki/architecture.md` (as built).

## What to do

1. Add per-route `headers` to `CaddyRoute`, rendered as a `header` directive
   inside the route's block. With no headers, the Caddyfile stays
   byte-identical (`node cli.ts --check` must pass before adding any).
2. Declare `/webmail` and `/webmail-api`. Check that synth's shadowing check is
   happy (the prefixes are disjoint) and that `handle_path` strips
   `/webmail-api`, so Stalwart sees `/jmap/...` and `/api/...`.
3. **Headers on `/webmail`:** the final CSP from brief 17,
   `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and
   `Permissions-Policy` minimal. `frame-ancestors 'none'` is part of the CSP.
4. If brief 04 found that Postern must be registered as an OAuth client with
   Stalwart, add it to `../vps-deploy/infrastructure/mail/plan.ndjson`.
5. Hand the owner the exact commands (`node cli.ts mail pre-deploy` for the
   Caddyfile, then the Postern deploy) and a smoke-test list:
   - sign in as `johndoe@example.com`;
   - read, send to another address on the same domain;
   - live update;
   - headers present (`curl -I`).

## Acceptance

- In `../vps-deploy`: typecheck, `--check` and a dry run of both stacks pass,
  and the Caddyfile diff shows only the new blocks.
- After the owner deploys: `/webmail` signs in and reads the
  owner's mail. `curl -I` shows the CSP. No request goes to `mail.<domain>`
  from the page.
