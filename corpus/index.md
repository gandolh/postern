- [wiki/architecture.md](wiki/architecture.md) - How Postern is put together, as built (briefs 01-17, 2026-10-20). The three workspaces (jmap client, web app, dev mail server), the request path through Caddy to Stalwart on the same origin, JMAP session-URL rebasing, sign-in with OAuth and PKCE through Stalwart's own endpoints (verified and built in brief 04: the /api/auth and /auth/token shapes, the TOTP retry, refresh without rotation, token lifetimes, no revocation, the account page URL), live updates by fetch-streamed event source plus Web Push, where state lives, local development, and the deploy as built in brief 18 (a static stack for /webmail with its headers, and the allowlisted /webmail-api route in the mail stack of ../vps-deploy; not deployed yet).
- [wiki/decisions.md](wiki/decisions.md) - Locked calls for Postern, each with date, rejected alternatives and reason. Own Gmail-like app rather than an existing client; JMAP not IMAP; no backend of its own; served at the root of its own host, postern.<domain>, with Stalwart at /webmail-api on the same host (revisited 2026-10-21 from /webmail on the shared estate origin, and what that cost); labels are JMAP mailboxes and archive means leaving the Inbox; message HTML only in a sandboxed iframe; tokens in memory only, and no staying signed in across a reload (owner, 2026-10-20); Postern not registered as an OAuth client; display settings and label colours kept per device (owner, 2026-10-20); no offline mail (owner); closed-app notifications show sender and subject; the house stack; Base UI under the overlays, with the composer window left native. Read before proposing to change any of these.
- [wiki/design.md](wiki/design.md) - How Postern looks and behaves. Gmail's familiar layout (top bar with search, left navigation with Compose, conversation list, reading pane, floating composer) in Postern's own visual identity, never Google's colours, logo or wordmark. The chosen visual system (brief 05) - patina-on-limestone palette with light and dark hex values and contrast ratios, Atkinson Hyperlegible Next and Mono, lucide icons, the three density metrics, the mark - plus the settings it supports and the motion and accessibility targets. Read before any UI brief; impeccable works within it.
- [wiki/glossary.md](wiki/glossary.md) - Postern's vocabulary, one canonical word per concept with the synonyms it replaces, mapping Gmail's words (what the UI says) to JMAP's (what the jmap package says). Conversation, message, label, system label, Inbox, archive, All Mail, star, Spam, draft, composer, identity, snippet, reading pane, keyword, mailbox. Use these words in code, UI copy and briefs.
- [wiki/gmail-on-jmap.md](wiki/gmail-on-jmap.md) - Which Gmail feature maps to which JMAP object or method on Stalwart 0.16, and whether it is native, client-side, needs checking, or impossible without server work. Conversations, labels and archive, stars and unread, search operators, drafts and sending, undo send, signatures, vacation, filters, spam, contacts, push, attachments, quota, and the Gmail features deferred to todos. Read before writing or working any feature brief.
- [wiki/open-questions.md](wiki/open-questions.md) - Genuinely unresolved questions as of 2026-10-22, each naming the brief or owner call that settles it. Whether production should shorten Stalwart's token lifetimes, since tokens cannot be revoked; whether Postern should keep a session across reloads now that it has its own origin. Delete an entry the moment it is answered.
- [wiki/overview.md](wiki/overview.md) - What Postern is in a paragraph. A Gmail-like webmail for the owner's own mail on the production domain, a static web app at the root of its own host, postern.<domain>, that talks JMAP to the estate's Stalwart server, with no backend of its own. Who uses it, what it copies from Gmail, what it leaves out, and where the other pieces live.
- [wiki/security-findings.md](wiki/security-findings.md) - Every security finding from brief 17's whole-repo review (2026-10-20), by severity, with file and line, what an attacker gets, and whether it was fixed (with its test) or is open and whose lane the fix belongs in. The High one, the service worker's precache any script on the shared origin could rewrite, is fixed (hashes baked into sw.js, checked on every read). Read before working on the service worker, push, prefs, filters or anything the shared origin can reach, and when picking security follow-ups.
- [wiki/security-headers.md](wiki/security-headers.md) - The HTTP headers production sends for Postern and /webmail-api on postern.<domain>, final since brief 17 (2026-10-20), on its own host since brief 19 (2026-10-22). The exact CSP and why each directive is there (style-src 'unsafe-inline' exists only for the message frames, and why it cannot go), COOP, CORP, Permissions-Policy, nosniff, no-referrer, X-Frame-Options, the /webmail-api path allowlist, which screens were proven under them, and the Caddy route shape ../vps-deploy renders. Read before changing a header or the Caddy route.
- [wiki/security.md](wiki/security.md) - Postern's threat model and the rules that answer it. Untrusted message content (HTML, links, look-alike hosts, remote images, attachments, spoofed senders), its own host since 2026-10-22 (another estate app can no longer reach it) and what a script on Postern's own origin could still do, token handling (memory only, no revocation in Stalwart, the 8-hour idle timeout, the bounded last work before a sign-out, the failed-password ban threshold), the sandboxed-iframe rendering rule and why CSP inheritance makes "show images" work, and the browser tests that prove it (web/e2e). Headers are in security-headers.md, open findings in security-findings.md. Read before touching message rendering, sign-in, storage or headers.
- [wiki/status.md](wiki/status.md) - Snapshot as of 2026-10-22. Briefs 01-19 are done (built and verified against the local Stalwart; brief 18 prepared the deploy in ../vps-deploy, 19 moved Postern to the root of postern.<domain>), nothing is deployed yet. One line per brief in the order they ran, the parked todos, and the owner steps (deploy and smoke test, screen reader, Android install, real push, token lifetimes).
